This screen — Edit post (/admin/posts/{id}/edit)

  • Edits every field of an existing post, prefilled (§4.1).
  • Same layout as "New post" but with values filled in.
  • Autosave applies to drafts and published posts alike; it never changes publication state. For a published post (like this one) an autosaved edit goes live immediately, so the indicator reads "saved & live at HH:MM" (§4.1, §7.5).
  • A "Delete this post" button sits below, separated by a top border; deleting opens a confirm dialog first (§7.5 Confirm dialog).
  • The publication date sits beside the status as a plain ISO text field (YYYY-MM-DD, not a locale date picker), prefilled with the post's current date. Changing it re-dates the post and moves it in the newest-first lists; it is a label, not a schedule. Blank (a never-published draft) means "stamp it when published" (§4.1, §5.1, §7.6).
  • No slug field — the slug is service-managed. Editing a published post's title regenerates its slug (and public URL); reverting to draft clears it (§5.2).
  • On save, a published post redirects to its public page; a Hangul slug must be encodeURIComponent-encoded in the redirect to avoid a header error (the earlier 500 cause).
